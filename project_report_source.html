Executive Summary & System Scope

The Hostel Maintenance and Complaint Tracker is a high-reliability, role-segregated web application designed specifically for the residents and administration of Aquamarine Hostel at IIT (ISM) Dhanbad. It replaces error-prone physical complaint registers with a secure digital workflow encompassing student issue logging, institutional email verification, strict ticket access controls, live metric tracking, and administrative resolution management. Built with vanilla PHP 8.2, MariaDB (PDO), and modern CSS3/JavaScript, it eliminates external framework bloat while enforcing enterprise security principles.

🎓 Student Portal Architecture Secure login/signup with strict 24JE0329@iitism.ac.in validation, automatic identity binding, ticket lodging across 4 categories, and isolated complaint inspection.
🛡️ Warden Portal & Operations Administrative oversight with dynamic workload metrics (Submitted, In Progress, Resolved), and asynchronous status modification.
🔒 Enterprise Security Model 100% prepared PDO statements (SQL Injection immunity), cryptographic password hashing (BCrypt), strict input regex sanitization, and full XSS mitigation.
⚡ Lightweight Native Tech Stack Native PHP 8.2 • MariaDB 10.4 • Vanilla JavaScript (Fetch API) • Pixel/Flex CSS3 • Clean multi-portal routing without unnecessary dependencies.

Section 1: Architectural Design & Database Implementation

1.1 Multi-Tier System Architecture & File Structure

The application is structured around a decoupled multi-tier architecture separating presentation views, asynchronous API endpoints, and centralized database configuration. Direct access to the root URL (index.php) initiates a session-aware redirector routing users immediately to either the Student Portal or Warden Portal.

📁 Presentation Layer

student.php: Dual-state student portal (Auth vs. Dashboard).
warden.php: Administrative management console with metric widgets.
index.php: Clean root redirector without redundant home landing.

⚙️ API Controller Layer

api/submit_complaint.php: Validates & saves new tickets.
api/update_status.php: Warden-authenticated status mutator.
api/get_statuses.php: Asynchronous status synchronizer.

🗄️ Persistence & Assets

config/db.php: Centralized PDO database factory.
assets/style.css: Custom responsive CSS with zero margin collapse.
assets/script.js: Asynchronous Fetch controllers and modal popups.

1.2 Relational Database Schema (MariaDB/MySQL)

Data persistence is implemented using relational tables with strict foreign key constraints, UTF-8mb4 collation for full character support, and an auto-migration script ensuring password hashing columns exist dynamically.

1.3 Database Connection Factory (config/db.php)

The getDbConnection() function establishes a secure PDO connection with emulated prepared statements disabled, preventing SQL injection vulnerabilities at the driver level.

function getDbConnection(): PDO { $dsn = "mysql:host=127.0.0.1;port=3306;dbname=hostel_complaints;charset=utf8mb4"; $options = [ PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION, // Graceful error throwing PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC, // Associative row array mapping PDO::ATTR_EMULATE_PREPARES => false, // Native prepared statements (SQLi Immune) ]; $pdo = new PDO($dsn, 'root', '', $options); $pdo->exec("ALTER TABLE `students` ADD COLUMN `password` VARCHAR(255) NULL"); // Self-healing migration return $pdo; }

🔄 Root Redirector Logic (index.php)

Eliminating redundant public marketing pages, index.php executes immediate session checks: if $_SESSION['warden_logged_in'] is active, it redirects to warden.php; otherwise, it routes to student.php via HTTP 302 headers.

Section 4: Security Implementation, Verification & Conclusion
Aquamarine Hostel Maintenance Tracker
4.1 Defense-in-Depth Security Framework

The system implements comprehensive defensive measures across input handling, authentication, database transactions, and browser rendering to guarantee integrity during university lab evaluation:

🛡️ SQL Injection Immunity

100% of dynamic database queries utilize parameterized PDO prepared statements with ATTR_EMULATE_PREPARES => false, guaranteeing queries and parameters are parsed independently.

🔒 Cryptographic Hashing

Student passwords are stored as BCrypt hashes using PHP's native password_hash() and evaluated via password_verify(), preventing rainbow-table and plain-text leaks.

🛡️ Cross-Site Scripting (XSS)

All dynamic database output rendered to HTML passes through htmlspecialchars($var, ENT_QUOTES, 'UTF-8'), neutralizing malicious script injection.
